# The vision for reply blocks

An agent's reply can carry structure: a set of checks, a before-and-after, a comparison, ordered
steps, evidence for a claim. The plugin could draw all of it. Instead it turned every part into
ordinary paragraphs, so a change read as four unrelated sentences and a set of checks read as prose
with the word "status" repeated.

Meanwhile the recap card — the thing that ends a turn — was designed. A bordered card tinted by its
state, a label column, ticks, numbered steps, actions along the bottom. It was the only object in the
transcript that looked deliberated.

**The vision is that a reply's parts earn the same care.**

Not the same volume. The card is the turn's verdict and stays the loudest thing on screen. The parts
are the evidence it rests on, and evidence should read as evidence: quiet, aligned, scannable, with
colour spent only where a status or a choice needs it.

Three principles carry it:

- **Structure that exists should be visible.** A part whose data is a list of parallel rows gets a
  panel. A part with one subject gets a label and no panel. Prose gets neither, however deep it
  sits.
- **Status is shown, not spoken.** A mark, then a word, then a colour, in that order of importance,
  so passing and failing are distinguishable before anyone reads a line of text.
- **A failure has to be findable.** If a reply carries four panels and one holds a failed check, the
  failure belongs at that panel's own edge, not only inside it.

What it is not: a restyle of the recap card, a reason to box every paragraph, or a decorative system.
A part with one sentence stays a sentence.

When it works, a reply reads the way the card does — like something made, rather than something that
stopped mid-thought.
